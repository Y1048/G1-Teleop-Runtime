# Quest IP 자동 탐지

새 G1의 저장소 폴더에서:

```bash
git pull --ff-only
python3 discover_quest.py
```

1. Quest APK에서 서버 주소를 **G1 IP**로 설정하고 APK를 실행한다.
2. 스크립트가 UDP 5020에 들어오는 기존 양팔 입력 패킷을 기다린다.
3. 올바른 형식·증가하는 sequence/시간의 연속 입력과 짧은 관찰 구간을 확인한다.
4. 송신 IP를 표시하고 포트를 반환한 뒤 종료한다.
5. 화면에 출력된 무모터 검사 또는 실제 실행 명령을 **사용자가 직접** 실행한다.

**연결했다고 모터가 시작되지 않는다.** 이 도구는 입력 수신만 하며,
모터/heading/server/DDS/카메라 프로세스를 실행하거나 패킷을 전달하지 않는다.
APK 변경이나 전체 LAN 스캔도 하지 않는다.

기존 teleop 프로그램이 UDP 5020을 사용 중이면 중단한다. 기존 프로세스를 강제 종료하지 않는다.
여러 송신 IP 또는 세션이 동시에 보이면 선택하지 않고 중단한다.
기본 대기 시간은 60초이며 `--timeout 120`처럼 변경할 수 있다.

## 탐지가 확인하는 것

현재 APK 소스의 `g1.bimanual.unity.sim.v5`, `unity_display_world_v1` 계약에 맞는
양손 입력이 G1에 지속해서 도착했다는 사실이다. 이 계약에는 역사적인
`simulation_only=true` 필드가 남아 있으며 이를 모터 실행 허가로 해석하지 않는다.
손 추적/engage가 아직 되지 않아도 올바른 대기 입력 패킷이면 탐지할 수 있다.

패킷 형식은 암호학적 장치 인증이 아니다. 같은 형식을 보내는 다른 프로그램도 탐지될 수 있다.
이 검사는 카메라·피드백 등 G1→Quest 방향까지 정상이라는 보장은 아니다.
실제 장치 통신 검사는 출력된 `NO_MOTORS=1` 명령으로 별도 진행한다.
이 명령은 카메라 PTZ 등을 사용하며, 이 탐지 도구 자체와는 다르다.

Quest IP가 바뀌거나 오래 기다린 뒤 실행한다면 다시 탐지한다.
APK가 아직 G1 주소를 모르는 경우 이 도구만으로 상호 자동 발견되지는 않는다.

## 검증

생성 패킷을 이용해 단일/복수 장치, 복수 세션, 반복/오래된 입력, 잘못된 JSON,
nonfinite 값, 로컬 입력, 포트 충돌을 검사한다.
2026-10-20 PC에서 수신 루프·timeout·포트 반환을 포함한 자동 테스트 12개 통과.
이번 G1 SSH 접속은 완료되지 않아 G1 Python 환경에서의 재검사는 수행하지 못했다.
실제 Quest APK를 착용해 진행하는 연결 검사는 아직 수행하지 않았다.
기존 실행 패키지와 C++ 모터 프로그램은 변경하지 않았다.
